# 한글동행 문화카메라 데모·운영 인계

기준: **2026-10-07, day-of-v1-20261007 / API 계약 14:26 문화·카메라 확장**. 사용자 마감은 **15:00 기능 동결 → 15:30 핵심 QA 종료 → 15:45 문서·push → 16:00 개발·검증·push 완료 및 인계**, 공식 제출 17:20, 발표+데모 5분이다. 커밋·push·배포는 root 담당이다.

**주 시연: Android Chrome + 현재 공개 HTTPS + 후면 카메라. 예비: 노트북 Chrome.** 이 문서는 운영 절차 초안이다. 촬영 대상·구도·샷리스트는 pG 문서를 따른다. root GO 전에는 로컬 문서·소스 확인만 하며 브라우저 접속·카탈로그 조회·사진 전송·모델 요청 등 라이브 요청을 하지 않는다.

## 확인된 범위와 새 기능 상태

| 구분 | 현재 인계 상태 |
|---|---|

| 시연 PC Chrome 한·영 마이크와 TTS 정상 재생 | 사용자 확인 완료. 음성 중지·언어 전환 등 세부 예외 동작까지 확인한 것은 아님 |

| 식이 의미 처리·원거리 JSON | 기존 수리·재검수 상태 유지. 새 PASS 인계 전 기본 데모 제외 |

작성자는 라이브 요청·GPU 호출·서비스 재시작을 하지 않았다. health·단위 테스트·기존 GPU 성공·OpenShell 통제 증거는 범위를 구분한다. 새 문화 경로의 실효 정책·실제 호출과 저장까지 root/infra가 확인해야 한다.

[API 계약 14:26](../shared/api-contract.md), [pQ 발표 개요](presentation/발표개요.md)·[발표자료](presentation/발표자료.md), [p8 웹 README](../web/README.md)·[웹 인계](../web/BUILD-WEB-01.md), [빌드 상태](BUILD-STATUS.md)·[라이브 QA](qa/live-checklist.md)를 대조한다. 오래된 음식 전용 문구보다 14:26 계약을 우선한다. p8 문서가 갱신 중이어서 버튼 예정명은 [CameraPanel](../web/src/CameraPanel.tsx)·[카메라 제어](../web/src/useCamera.ts)·[자동 분석 스케줄러](../web/src/autoCompanion.ts)도 읽어 확인했다. 코드 존재를 배포 완료라고 판단하지 않는다.
2. root가 통합 빌드·worker 준비와 **이번 문화카메라 라이브 GO**를 명시하기 전에는 자동동행을 켜거나 요청을 보내지 않는다. 기존 음식 QA의 GO를 새 경로에 자동 적용하지 않는다. 기존 broker·worker·GPU를 재시작하지 않고 Windows/WSL broker도 중복 실행하지 않는다.
3. 공개 URL은 제품 루트에서 **로컬 상태 파일의 지정 필드만** 읽는다. 임시 주소를 문서에 고정하지 않는다.

```powershell
Set-Location C:\Users\USER\Desktop\hangul-donghaeng
$demoPreview = Get-Content -LiteralPath '.runtime/mobile-preview/state.json' -Raw | ConvertFrom-Json
$demoPreview | Select-Object url, status, checked_at
```

root GO 후 표시된 URL을 Android Chrome에서 연다. Android에서 PC의 `localhost` 주소를 사용하지 않는다. URL 기록만으로 현재 접속 성공을 판단하지 않고 서비스·세션·worker와 정적 빌드 일치를 운영자가 확인한다. 내부 모델 주소·인스턴스·조직·토큰·전체 환경값은 공개하지 않는다.

4. 공개 HTTPS 터널이 없는 경우에만 infra/root가 기존 프로세스·준비된 `web/dist`·broker를 확인한 뒤 아래 절차를 사용한다. 이 문서 작업자는 실행하지 않는다.

```powershell
& .\infra\mobile-preview.ps1
```

스크립트는 터널을 생성하고 필요 시 도구를 내려받는다. 기존 기록 프로세스가 살아 있으면 중복 실행을 거부한다. 새 URL이면 root가 정확한 origin·쿠키 설정을 확인한다. 시연자는 `-Stop`·서비스 시작/재시작을 실행하지 않는다. 완전히 중지된 환경의 최초 기동은 [README](../README.md)의 해당 Windows/WSL 절차와 infra 인계를 운영자가 수행한다.

5. Android에서는 root GO 후 **카메라 시작 / Start camera**를 눌러 권한을 허용하고 실제 후면 화면인지 확인한다. 사용자가 Android 후면 카메라와 캡처 후 사진 유지를 확인했다. 시연 시에도 실제 후면 화면인지 확인한다. 미리보기는 로컬이고 카메라 오디오는 수집하지 않는 설계다. 마이크 질문은 별도 버튼으로 켠다. 기본 상태에서 **자동동행 / Automatic companion**은 끈 채 시작한다.
6. pG가 정한 공개·허용 장면을 사용하고 사람 식별·개인 사진·원본 로그를 노출하지 않는다. 노트북에는 검증된 기존 결과와 공개 음식 샘플 `data/samples/samgyetang-960.jpg`를 예비로 준비한다. 이 샘플은 특정 식당·재료·판매 여부의 증거가 아니다. 다른 장치의 결과·세션 쿠키가 자동 공유된다고 가정하지 않는다.

## Broker·SSH 터널 lifecycle 인계 — root 실행 후

**최신 root 수정·검증 인계:** `WSLENV`가 미설정 값을 빈 문자열로 전달해 `.env`의 origin 설정을 가리면서 모든 origin의 세션 요청이 403이 되었다. root가 `Popen` 전에 빈 `GUIDE_ALLOWED_ORIGINS`·`GUIDE_COOKIE_SECURE`를 자식 환경에서 제거하도록 수정했고, 소유 broker 재시작 후 실제 `POST /api/sessions` **200**을 확인했다. 현재 detached broker는 **Linux PID `2629442`**다. worker12는 **배포 준비 완료**로 인계받았다. 작성자는 helper의 수정 코드를 읽기 전용으로 확인했으며, 세션 요청·재시작은 추가하지 않았다. 기존 README 기동 절차를 유지한다.

**2026-10-07 root 실행 인계:** 기존 broker PTY55926 / WSL PID1789203과 터널 PTY50918을 종료했지만, SSH 터널의 8001 리스너는 남았다. 이 터널은 helper가 시작·소유한 프로세스가 아니므로 그대로 유지한다. PTY 번호를 OS PID로 사용하거나 살아 있는 터널을 임의 종료·인수하지 않는다. cloudflared 공개 HTTPS 터널과 이 NVIDIA 연결용 SSH 터널은 별개다.

root의 최초 `Start All`은 Windows `Start-Process`의 새 실행 컨텍스트에서 `WSL_E_DISTRO_NOT_FOUND`로 실패했다. root가 Windows Start 분기를 동일 컨텍스트의 직접 `& $wsl` 호출로 수정했고, Linux 자식의 `start_new_session=True`와 파일 표준출력/오류 분리는 유지했다. **이 root 수정은 보존한다.** 아래는 root가 이미 성공시킨 Broker 단독 시작의 명령 형식이며, 현재 다시 실행할 절차가 아니다.

```powershell
# 실행 이력 설명용: 재실행 금지. 배포판 값은 root가 사용한 기존 값.
& .\infra\local-demo.ps1 -Action Start -Component Broker -Distro '<기존 WSL 배포판>' -RootGo
```

아래는 작성자가 **15:39:07 KST에 `-Action Status`만** 실행한 **교체 전 관측 기록**이다. PID `2398958`은 최신 broker PID가 아니다:

| 대상 | 읽기 전용 관측 | 운영 판단 |
|---|---|---|
| Broker / 8000 | `owned_running=true`, Linux PID `2398958`, `port_listening=true` | helper가 기록한 프로세스와 현재 PID 식별값 일치 |
| NVIDIA SSH 터널 / 8001 | `owned_running=false`, helper PID `null`, `port_listening=true` | 리스너는 존재하지만 helper 소유가 아님. 기존 터널 유지 |
| 두 구성요소의 `runtime_verified` | 모두 `false` | 이 Status는 health·worker·NVIDIA 모델 준비·문화 경로 PASS를 검증하지 않음 |

root는 Broker 단독 시작 후 health의 worker 상태가 true라고 인계했다. **broker health와 NVIDIA 터널/모델 준비 상태의 최종 확인은 root가 진행 중**이며, 작성자는 health·모델 요청을 추가하지 않았다. 당시 Status 확인 전후 helper SHA256은 `ad96f0ed9da40964d53ad8b402b7a82ae217bc42c3b6bc8de6d2b82a4a580768`로 같았다. 현재 프로세스가 보인다는 사실만으로 Codex 종료 후 유지까지 검증됐다고 말하지 않는다.

- **broker 교체로 메모리 세션이 초기화되었다.** Android와 노트북 모두 자동동행·카메라를 끄고, root의 접속 준비 확인 후 현재 HTTPS 페이지를 새로고침한다. 연결이 필요하면 **다시 연결 / Reconnect**를 한 번 눌러 새 세션을 확인한다. 이전 화면의 사진·작업·활성 결과가 새 broker에 남아 있다고 가정하지 않으며, 이미 다운로드한 카드만 별도로 보존한다.
- 기존 세션 사진 20장 한도에서 임의 새로고침으로 한도를 우회하는 절차와는 다르다. 이번 새로고침은 **root가 완료한 broker 교체 후 세션 복구**에만 적용한다.
- 문화카메라 라이브 GO가 따로 확인되기 전에는 새 사진·자동 프레임·모델 요청을 보내지 않는다. `Start All`, `Start Tunnel`, `Stop`을 추가 실행하지 않는다. 기존 터널과 최종 lifecycle 인계는 root가 결정한다.
- SSH 별칭 값은 기존 비공개 환경변수/SSH 설정에 둔다. 별칭·자격 증명·런타임 전체 로그를 문서나 공개 화면에 옮기지 않는다.

## 위치 기준: 공식 근거 카탈로그 선택과 GPS 분리

root GO 후 UI가 `GET /api/catalog`에서 받은 **검수된 수록 장소 anchor** 중 사용자가 선택한다. 아직 목록이 없거나 문화 항목이 배포되지 않았으면 임의 장소 ID·좌표·버튼을 만들어 시연하지 않는다. 목록 UI의 최종 버튼명은 p8 배포본과 대조한다.

- anchor 선택은 `location.origin='selected'`다. **사용자가 선택한 검색 중심**으로 말하며 ‘내 GPS’라고 부르지 않는다. 사진에서 좌표를 추정하지 않는다.
- 사진 속 장소 후보를 확인하는 행동과, 주변 검색의 중심을 선택하는 행동은 구분한다. 카탈로그에서 경복궁 등을 선택했다고 사진 인식이 맞았다는 증거가 되지는 않는다.
- 문화 장소 주변 식사는 먼저 그 장소의 카탈로그 anchor를 사용자가 선택/수락한 뒤 요청한다. 거리는 그 요청의 선택 중심 기준이며 직선거리다. 장소 카드 선택만으로 중심이 자동 이동한다고 가정하지 않는다.
- 실제 GPS는 **내 위치 사용 / Use my location**으로 사용자가 허용한 경우에만 GPS로 표시한다. 결과는 수록 문화 장소·식당 범위이며 전국 검색·도보 경로가 아니다. 운영시간·재료·식이 안전을 추정하지 않는다.

## 문화 중심 90초 운영 흐름 — 새 경로 QA 통과 조건부

pQ 발표의 **120–210초 데모 슬롯**에 맞춘 목표 편성이다. 모델 처리 시간 실측이나 90초 완료 보장이 아니다. 새 버튼은 개발 중 코드의 예정명이며 실제 배포본에서 존재·동작을 확인한 뒤 사용한다. 선제 질문은 실제 도착했을 때만 보여 주고, 임의로 에이전트가 먼저 물었다고 연출하지 않는다.

| 구간 | 운영자 조작 | 성공 범위·분기 |
|---|---|---|
| 0–15초: 문화 장소 보기 | Android Chrome HTTPS에서 **카메라 시작** → 후면 미리보기 확인. 자동 분석 QA까지 통과했다면 사용자가 **자동동행**을 명시적으로 켠다. | 로컬 미리보기와 샘플 프레임 분석을 구분한다. 연속 영상 전체를 모델이 실시간 분석한다고 말하지 않는다. |
| 15–35초: 선제 질문·캡처 고정 | 실제 선제 확인 질문이 도착하면 읽고 사용자 확인을 받는다. **사진 고정 촬영 / Capture a photo** → 고정된 장면 확인 → “이곳의 한글 이름과 역사·문화 맥락을 알려 주세요.” 입력 또는 마이크로 말한다. | 고정 촬영은 자동동행을 끄고 사진을 고정하는 설계다. 캡처만으로 수동 질문이 전송됐다고 보지 않는다. 자동 요청이 처리 중이면 끝날 때까지 기다린다. 선제 질문이 늦으면 자동동행을 끄고 수동 경로로 좁히며 ‘선제 질문 미시연’으로 기록한다. |
| 35–60초: 이름·근거 확인 | **함께 알아보기 / Explore with me** 또는 **이어서 물어보기 / Keep exploring**로 고정 사진 질문 전송. 실제 장소 후보가 나오면 확인하고 **출처와 판단 이유 / Sources & what we considered**를 펼친다. | 한글 장소명·역사 문장에 맞는 출처·시점·미확인을 확인한다. 불분명하면 추가 질문/모름으로 남긴다. 출처 ID만 있으면 사실이라고 단정하지 않는다. |
| 60–75초: 주변 식사 | 확인한 문화 장소의 **수록 anchor를 명시적으로 선택** → 반경 **1 km** → “선택한 문화 장소 주변의 수록 식당과 확인할 점을 알려 주세요.” | 문화 장소→식사 방향의 실제 통과 범위만 보여 준다. 식당→문화 장소는 root가 별도 통과를 확인했고 시간이 남을 때만 추가한다. 빈 결과는 수록 범위 내 결과 없음이다. |
| 75–90초: 저장·종료 | 최신 활성 답변에서 **HTML**, **JSON** 다운로드 → 카드의 장소·문화 근거·선택 위치·미확인 항목 확인 → **자동동행 해제**, **카메라 중지 / Stop camera**. | root가 검수한 해당 저장 결과만 완료로 말한다. 문화 카드가 후속 식사 답변으로 교체될 수 있으므로 문화 결과 보존이 필요하면 식사 요청 전 따로 저장한다. 한 카드에 전체 대화가 합쳐진다고 가정하지 않는다. |

자동 분석 첫 대기와 모델 응답까지 들어가므로 선제 질문·문화 답변·식사·저장을 모두 90초에 넣을 수 있는지는 실기기 리허설로 확인한다. 지연 시 단계를 생략해 성공으로 포장하지 않는다. root가 통과한 수동 문화 경로만 시연하거나, 사전 생성 결과임을 밝힌 검수된 카드로 전환한다. 새 문화 경로가 미통과면 아래 노트북 예비를 사용한다.

## 자동 프레임 운영 제한 — 계약 준수, 실제 PASS 대기

- **명시적 선택**으로만 자동동행을 켠다. 샘플 JPEG만 기존 사진 업로드 경로로 보내고 연속 영상 전체 업로드·저장으로 설명하지 않는다. 얼굴·사람 식별을 하지 않는다.
- 다음 자동 요청은 **이전 요청 완료 후 최소 20초**가 지난 뒤다. 20초마다 중첩 전송하거나 20초 응답 속도를 보장하는 의미가 아니다. **자동 요청은 한 번에 하나**만 처리하고 반복 제안·반복 낭독을 억제한다.
- 수동 편집·질문·음성 입력·처리 중·후보 확인 대기에는 자동 분석을 일시 중지한다. 수동 조작을 우선하며 운영상 이미 처리 중인 작업이 끝난 뒤 다음 질문을 보낸다. **새 질문 보내기** 연타로 부하를 겹치지 않는다.
- **자동동행 해제**는 다음 자동 요청을 막는다. **카메라 중지**는 로컬 미디어를 닫는다. 이미 서버로 보낸 작업이 취소됐다고 단정하지 않는다.
- 탭 숨김·앱 전환·화면 잠금에서는 자동 분석이 멈춰야 한다. 개발 중 카메라 코드는 숨김 시 스트림을 종료한다. 복귀 시 새 전송이 없는지 확인하고 사용자가 다시 카메라를 시작·자동동행을 선택한다. 권한 거부나 카메라 종료 시에도 전송을 지속하지 않는다.
- **세션 사진 20장 한도**에 도달하면 보이는 안내와 함께 자동동행을 멈춘다. 자동 업로드도 한도에 포함된다. 몰래 이전 캡처를 지우거나 세션을 바꾸어 계속 분석하지 않는다. 기존 카드를 먼저 저장하고 이후 세션 처리는 root에게 인계한다.

## 실패·예비 전환

| 상황 | 운영 절차 |
|---|---|
| Android 카메라 권한 거부·후면 화면 아님·미리보기 실패 | 자동동행을 끄고, 카메라가 켜져 있으면 **카메라 중지**. root GO 범위에서 **사진 선택**으로 pG의 허용 장면을 고른 뒤 질문을 확인해 수동 전송한다. 파일 선택도 불가하면 노트북의 검수된 사전 결과로 전환한다. 무대에서 권한 설정을 반복 변경하지 않고 해당 실패 회차를 카메라 PASS로 기록하지 않는다. |
| 휴대폰 HTTPS 접속 불가·인증서 경고 | 현재 URL을 로컬 상태 파일에서 재확인하고 root GO 후 Android **Chrome**에서 정확한 `https://` 주소를 연다. PC의 localhost·이전 터널 주소를 사용하거나 인증서 경고를 우회하지 않는다. 페이지 자체가 안 열리면 노트북의 검수된 사전 결과로 전환하고 infra/root가 터널·origin을 확인한다. 새 터널 임의 생성과 broker·worker·GPU 재시작 금지. |
| 페이지는 열리지만 연결·세션 오류 | **다시 연결 / Reconnect** 또는 **연결 새로고침** 한 번만 시도한다. 계속 실패하면 추가 업로드를 멈추고 노트북 예비로 전환한다. 다른 장치와 세션·저장 카드가 자동 공유되지 않는다. 쿠키·토큰을 옮기거나 공개하지 말고 root에게 관측 시각·오류 문구만 전달한다. |
| 자동 요청 중첩·중지 후 재전송·백그라운드 전송 | **자동동행 해제 → 카메라 중지**. 그래도 새 전송이 계속되면 해당 브라우저 탭을 닫아 클라이언트 동작을 끝내고 자동 모드를 시연에서 제외한다. root/p8에 관측 시각·증상만 전달한다. 이미 서버에 제출된 작업은 계속될 수 있으므로 종료·취소됐다고 말하지 않는다. 복귀 시 root 확인 전 자동동행을 다시 켜지 않는다. |
| 세션 사진 20장 한도 | **자동동행 해제 → 카메라 중지 → 가능한 최신 활성 카드 저장** 후 새 캡처·업로드를 멈춘다. 이미 저장한 카드 설명으로 마무리하거나 노트북의 기존 검수 결과로 전환한다. 새로고침·다시 연결이 한도를 초기화한다고 가정하지 않는다(`POST /api/sessions`는 유효 세션을 재사용). 캡처 삭제·자동 세션 교체로 우회하지 않고, 새 세션 필요 여부는 root에게 인계한다. |
| 사진 형식·크기 오류 | 한도 오류가 아닌지 먼저 확인한다. 한도에 여유가 있고 root GO 범위일 때만 **사진 선택**으로 JPG/PNG·8MB 이하 허용 파일을 다시 고른다. 사진 20장 한도에 도달했다면 이 재업로드 절차를 사용하지 않는다. |
| 장소 후보 불명·카탈로그 anchor 없음 | 장소를 지어내거나 사진을 GPS로 설명하지 않음. 사용자 확인을 받거나 문화 경로 미시연으로 남김. 공식 근거가 없는 역사 설명을 보충하지 않음. |
| 모델 시간 초과·대기 지속·구조화 결과 오류 | **자동동행 해제 → 카메라 중지**, **다시 시도/새 질문 보내기**를 반복 누르지 않는다. 브라우저 시간 초과가 서버·GPU 작업 종료를 뜻하지 않는다. root가 기존 요청의 종료 상태와 실제 오류를 확인할 때까지 추가 전송 없이 검수된 ‘사전 결과’로 전환한다. 재시도는 root가 준비를 확인한 뒤 한 번만 수행하고 다시 실패하면 해당 라이브 경로를 종료한다. 스키마 오류를 빈 성공 결과로 대신하지 않는다. |
| 식이 문장 부정확·원거리 결과 오류 | 해당 흐름 제외. 안전 보장 금지. 의미·빈 JSON·오래된 지도 마커를 수정 후 개별 재검수. |
| 마이크/TTS 실패 | 텍스트 입력·화면 설명으로 진행. PC 한·영 마이크/TTS와 Android 한·영 마이크의 사용자 확인 기록은 보존한다. **Android TTS는 확인 대기**이며 실패 회차·장치를 따로 기록한다. |
| 다운로드 실패 | 같은 장치·세션의 최신 활성 결과에서 확인. 다운로드 실패를 완료로 말하지 않음. 세션 쿠키나 결과 링크를 공개 공유하지 않음. |

**노트북 예비:** Android에서 자동동행 해제·카메라 중지 → 노트북의 검수된 기존 결과 탭으로 전환한다. 기존 음식 라이브 재시연이 root GO 범위에 있을 때만 **사진 선택 → 공개 삼계탕 샘플 → 서촌 시연 위치·1km → 질문 → 필요한 음식 확인 → 출처·한글 문장 → HTML/JSON 저장**을 수행한다. 이미 검수된 결과를 보여 주면 사전 결과임을 밝힌다. 문화 화면은 ‘개발 중/실제 PASS 대기’라고 설명한다. 노트북에도 문화 경로가 통과했다면 그 통과 범위만 대체 시연한다.

## 선택: 가상 TASK — 기본 90초 밖

root가 별도 GO와 준비를 확인하고 시간이 남을 때만 사용한다. **자동동행 해제·카메라 중지·카드 저장** 후 하단 **연결 상태와 개인정보 → 가상 자료로 연습 일정 만들기 → 반나절 문화 여행 → 함께 알아보기** 순서다. 가상 배너와 실제 지도 분리, 일정·이동 여유·상충 공지의 적용 근거를 확인한다. 실제 장소가 섞이면 중단한다. **여행으로 돌아가기** 후 이전 세션 결과·사진이 그대로 남는다고 가정하지 않는다.

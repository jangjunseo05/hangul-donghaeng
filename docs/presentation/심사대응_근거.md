## Q1. 역사·문화 중심으로 무엇이 달라지고, 문화유적과 식당을 왜 함께 다루나요?

**30초 답변**

> 여행자가 눈앞의 장소를 확인하고 그 역사에서 다음 방문 행동으로 이어가도록 돕습니다. 공식 자료를 조사해 경복궁과 정문 광화문, 토속촌 식당을 연결했습니다. 두 문화 지점은 같은 궁궐 단지이고 식당은 한 곳입니다. 실제 API에서 문화에서 식당으로 가는 흐름은 완료됐으며, 반대 방향은 수정 배포 후 검증 중입니다. 사용자 효용까지 입증됐다는 뜻은 아닙니다.

- **확인한 것:** 공식 문화자료 조사 완료와 `catalog_version=2026-10-07.2` 통합. 경복궁·광화문의 역사·운영·위치 근거를 구분하고 양방향 관련 장소를 연결했다. worker11 문화→식당은 `ready`이며 다운로드 결과 일치가 기록됐다.

- **증거 경로:** [제품 README](../../README.md), [카탈로그](../../data/catalog.json), [근거 레코드](../../data/evidence.json), [문화 서사 공식 근거](research/문화서사_공식근거.md), [모델 실행 스냅샷](../runtime/evidence/latest-model-execution.json).

## Q2. 왜 OpenShell이 필요한가요? 모델에게 금지하라고 지시하면 충분하지 않나요?

**30초 답변**

> 사진과 문서는 모델이 해석하는 불신 입력이라서 실행 권한을 별도로 제한했습니다. OpenShell은 worker의 파일과 네트워크 접근을 정책으로 통제합니다. 무해한 시험에서 허용 조회와 금지 파일·통신을 로그와 실제 수신 기록으로 대조해 11조건을 확인했습니다. worker12의 정책 로드도 확인했지만 모든 공격이나 답변의 사실성을 보장하지는 않습니다.

- **확인한 것:** OpenShell 0.1.2. 경계 결합 판정은 파일 거부·해시 보존·일반 권한 대조와 허용/금지 통신 등 **11조건 PASS**다. 15:49:54 KST의 worker12 readiness는 동일 검증 allowlist, 단일 consumer 배포, 실효 정책과 runtime ACK를 기록한다.
- **아직 모름:** worker12 전체 사용자 흐름과 의미 품질. 동일 allowlist와 정책 ACK는 11조건 시험 전체를 새 worker에서 재실행했다는 뜻이 아니다. 브라우저 기능 전체를 격리했다는 뜻도 아니다.
- **증거 경로:** [SECURITY-EVIDENCE](../runtime/SECURITY-EVIDENCE.md), [경계 결합 판정](../runtime/evidence/boundary-combined-verdict.json), [최신 배포 준비](../runtime/evidence/latest-readiness.json), [NVIDIA 기술 근거](research/NVIDIA_기술근거.md).
- **추궁 시:** 모델의 거절 문장·서버 인증 오류·OpenShell의 실행 거부는 다른 증거다. 실제 금지/비밀 영역을 열어 시험하지 않았다.

## Q3. 정확히 무슨 권한을 주었고, 파일 삭제·다른 사용자 정보 접근은 어떻게 막나요?

**30초 답변**

> worker는 코드와 자료를 읽고 지정된 작업 서버와 모델 목적지에 통신합니다. 영구 파일은 worker가 직접 쓰지 않습니다. trusted broker가 요청 소유권과 근거·검색 결과를 검사해 카드를 저장합니다. 보호 파일의 쓰기·삭제 거부는 시험 사본으로 확인했으며, 쓰기 가능한 임시 폴더까지 삭제 불가라고 설명하지 않습니다.

- **확인한 것:** 비루트 worker, 읽기 전용 자료, 임시 공간 쓰기, REST `enforce`, provider 포함 실효 정책. worker12 정책 파일과 readiness의 파일 SHA·정책 ACK가 연결된다. 서버는 활성 요청·세션·근거 레코드·검색한 장소를 검사하고 JSON/HTML/Markdown 카드를 생성한다.
- **아직 모름:** worker12 UI 전 경로의 수용. 세션 검사는 앱 책임이며 파일 정책과 다르다. 관찰 중지·오래된 응답·요청 전환의 실제 UI 동작은 p8 검증 중이다.
- **증거 경로:** [정책 README](../../policy/README.md), [worker12 실효 정책](../runtime/evidence/worker-12-effective-policy.json), [배포 준비와 ACK](../runtime/evidence/latest-readiness.json), [broker 검사·저장 코드](../../service/main.py), [파일 경계 시험](../runtime/evidence/boundary-matrix-01.log).
- **추궁 시:** `read_write`는 삭제도 허용하며 `audit`는 기록 후 전달한다. 전체 정책·인증값·비공개 접속 식별자를 발표 화면에 펼치지 않는다.

## Q4. 왜 카메라 관찰이 필요하고, 연속 영상 전체를 보내는 건가요? 권한 경계는 어디인가요?

**30초 답변**

> 여행자가 질문을 아직 정하지 못해도 눈앞의 대상을 바탕으로 확인 질문을 제안하려는 기능입니다. 카메라 미리보기는 로컬에서 이어지고, 수동 캡처나 선택적 자동 관찰이 고른 정지 프레임을 분석합니다. 연속 영상 전체 추론은 아닙니다. Android 카메라·캡처 유지·한영 음성 입력은 사용자 확인이 있지만, 최신 worker12와 이어지는 전체 UI 검증은 진행 중입니다.

- **확인한 것:** README에 로컬 연속 미리보기·선택 프레임·수동 우선·중지 기능이 명시돼 있다. desktop/mobile 캡처 회귀 12건과 빌드 PASS는 BUILD-STATUS의 최신 프런트 인계다. Android 후면 카메라·촬영 후 캡처 유지·한영 음성 입력은 해당 실행본에 대한 사용자 보고다.
- **아직 모름:** 최신 worker12의 실제 자동 관찰·Android TTS·권한 거부/중지/백그라운드 전환·낡은 응답 처리. 이전 UI 회귀나 API 관찰 완료를 현재 전체 UI 통과로 확대하지 않는다.
- **검수 기준:** 관찰 상태·촬영/전송 범위 표시, 중지 뒤 새 캡처/전송 중단, 단일 처리·수동 우선, 오래된 결과/음성이 현재 대화를 덮지 않는지 확인한다. 이미 전달된 추론의 중단이나 제공자 보존까지 보증하지 않는다.
- **증거 경로:** [제품 구현 범위](../../README.md), [빌드·실기기 보고](../BUILD-STATUS.md), [브라우저 README](../../web/README.md), [브라우저 경계](../../policy/README.md), [최신 readiness의 UI 대기 상태](../runtime/evidence/latest-readiness.json).
- **추궁 시:** OpenShell은 worker를 통제한다. 브라우저 카메라·마이크·GPS·지도 권한을 대신하지 않으며 EXIF 제거가 얼굴 익명화를 뜻하지 않는다.

## Q5. NVIDIA 모델 API 키 없이 L40S에서 어떻게 실행했고, NVIDIA VL 모델은 무엇을 하나요?

**30초 답변**

> NVIDIA hosted API 대신 기존 Brev L40S에서 Nemotron Nano 12B v2 VL BF16을 vLLM으로 서빙합니다. 모델은 선택 사진의 후보와 의도를 판단하고 허용 자료·장소 조회를 거쳐 답변을 만듭니다. worker11에서 실제 모델 식별 일치와 호출이 확인됐습니다. 관찰 질문과 한국어 자료 표현 일부는 코드가 구성하며, worker12 전체 성공이나 NIM·NeMoClaw 사용을 주장하지 않습니다.

- **확인한 것:** L40S·vLLM 0.12.0·OpenShell 0.1.2. 15:46:05 KST 모델 실행 스냅샷은 **worker11**, 실제 응답 모델 식별 일치 6회와 허용 모델 POST 6회를 기록하며 상태는 `PARTIAL`이다.
- **아직 모름:** worker12 최신 모델/UI 수용과 문화 답변의 의미 품질. worker11 로그에는 요청 ID가 없어 6개 POST를 세 API 사례에 모두 일대일 귀속할 수 없다. readiness는 worker12, 모델 실행 스냅샷은 worker11이므로 버전을 섞지 않는다.
- **증거 경로:** [실제 런타임 구성](../runtime/README.md), [최신 모델 실행](../runtime/evidence/latest-model-execution.json), [최신 배포 준비](../runtime/evidence/latest-readiness.json), [agent 구현](../../agent/core.py), [NVIDIA 공식 설명과 구현 매핑](research/NVIDIA_기술근거.md).

## Q6. 프롬프트 인젝션과 잘못된 식이 답변까지 안전하다고 검증했나요?

- **확인한 것:** 최신 사용자/관리 인계의 Python **157+62 PASS**와 보존된 경계 **11조건 PASS**는 서로 다른 시험이다. worker11은 두 API 흐름 완료와 역방향 실패를 함께 기록한다. 데이터·모델 출력은 불신 입력이며 서버는 근거 레코드·인용 ID·장소·요청을 검사한다.
- **아직 모름:** 광범위 인젝션 저항성·탐지율, worker12 수정 뒤 한국어 의미 품질·음식→문화 결과, 식이 안전. 역사·한국어 의미 보완 코드가 배포됐다는 사실을 문장 품질 수용으로 바꾸지 않는다.

Python 157+62는 최신 인계 출처이며 BUILD-STATUS 15:45판의 154+62는 이전 보고다.

## Q7. 문화유적·식당의 장소를 사진으로 확정하나요? 가상 공통 TASK와는 어떻게 구분하나요?

**30초 답변**

> 사진은 장소 후보를 만드는 단서이며 확신이 부족하면 먼저 사용자에게 확인합니다. 공식 자료가 통합된 경복궁과 광화문은 궁궐과 정문의 관계로 설명하고, 식당 연계를 별도 방문 제안으로 다룹니다. 가상 TASK는 실제 지도와 분리합니다. worker11 관찰 결과도 확인 필요 상태였으며, 역방향 전환의 수정 결과는 현재 검증 중입니다.

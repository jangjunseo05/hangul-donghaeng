# 한글동행 촬영·시연 계획 — 라이브 한 흐름, 백업 90초

갱신: 2026-10-07 / owner w1:pG / 검수 root·발표 담당. 최신 root 전달사항을 반영한 계획이다. 이 문서 작업에서는 촬영·GPU 호출·서비스 변경을 하지 않았다.

## 현재 상태와 장치

- **주 장치: Android Chrome.** 후면 카메라·캡처와 한국어/영어 마이크 입력은 **사용자 확인 PASS**다. 이는 작성자의 독립 재시험 결과가 아니다.
- **Android TTS는 확인 대기**, **agent09는 root의 PASS 대기**다. 최신 프런트엔드의 6/6·빌드 준비 완료는 root 전달 상태이며, 실제 UI 녹화는 root09 PASS 이후 진행한다. 카메라·마이크 성공이나 프런트엔드 검사 결과를 문화 답변의 정확성·agent09 전체 성공으로 확대하지 않는다.
- **예비: 노트북 Chrome.** 실제 성공한 브라우저 흐름과 녹화 백업을 준비한다. 사진 업로드를 사용하면 카메라 촬영으로 소개하지 않는다.
- 공개 HTTPS는 제품 **`.runtime/mobile-preview/state.json`의 `url` 값만 참조**한다. 촬영 직전 root가 관리하는 최신 주소를 Chrome에서 직접 연다. 주소를 문서에 고정하거나 터널을 새로 만들지 않는다.

## 5분 발표 안에서 실행

[발표개요](발표개요.md)의 기존 배치를 유지한다: 설명 **0–120초**, **라이브 한 흐름 120–210초**, 보안·검증·마무리 **210–300초**. 전체 **300초**이며 라이브 대기시간도 포함한다. 90초 백업 영상은 라이브를 대체하거나 남은 슬롯 안에서 발췌한다. 라이브와 백업을 각각 90초씩 더하지 않는다.

기본 흐름은 **문화 샘플 보기 → 자동 관찰의 첫 확인 질문 → 사용자가 장소·지도 기준점 확인 → 질문 전송 시 현재 프레임 캡처 → 출처·한글 이름·문화 설명 → 주변 식당 지도 → 카드 저장**이다. 라이브에서는 이 한 흐름만 수행한다. 최종 빌드의 실제 성공과 90초 내 진행은 root09 PASS 뒤 리허설로 확인한다. 자동 관찰과 수동 질문을 겹쳐 실행하지 않는다.

**09 변경 방향(실행 검증 대기):** 사용자가 활성화한 자동 관찰은 샘플 프레임으로 **NVIDIA Decision 1회**를 수행하고, 불확실한 후보·맥락을 확인하는 **첫 질문만** 반환한다. 이 단계에서는 역사 주장을 만들지 않는다. 사용자가 확인한 뒤의 수동 질문에서 문화 근거가 있는 설명·주변 식당·저장 결과로 이어간다. 첫 질문의 가치와 이후 근거 있는 답변을 구분해 소개하며, 1회 호출 동작도 root의 실제 검증 전에는 실측 완료로 발표하지 않는다.

**최신 화면 캡처 방식:** 카메라가 켜진 상태에서 질문을 전송하면 현재 프레임을 캡처한다. 사용자가 명시적으로 화면을 고정한 경우에만 그 고정 사진을 사용한다. 기본 동작을 “처음 찍은 장면을 계속 기억한다”로 설명하지 않는다. 녹화에서는 실제 고정 여부와 질문에 연결된 장면을 보여준다.

진행자 질문 예시: **“광화문으로 확인했습니다. 선택한 광화문 지점에서 역사를 출처와 함께 설명하고 주변의 수록된 식당을 찾아 주세요.”** 실제 UI에서 확인값과 카탈로그 기준점을 선택한 뒤 사용한다. 지도 위치는 사용자 선택이며 GPS 실측이 아니다. root가 agent09 PASS를 확인하기 전에는 최종 성공 흐름으로 확정하거나 실제 UI 녹화를 시작하지 않는다.

## 촬영 전 최소 준비

1. `data/samples/heritage-demo.jpg`를 별도 모니터에 크게 띄운다. `data/samples/heritage-license.json`의 사진 출처·CC0·해시·표시 문구를 촬영 담당이 확인한다. Wikimedia Commons 공개 기록 사진이며 국가유산기관의 현장 사진으로 바꾸어 설명하지 않는다.
2. Android에서 방해금지·충전·저장공간을 확인하고 최신 HTTPS 페이지를 연다. 참가자 얼굴·명찰·개인 알림·개인 사진·토큰·콘솔이 촬영 범위에 들어오지 않게 한다.
3. 후면 미리보기로 모니터를 비추고 반사·초점을 맞춘다. 마이크는 사용자가 직접 눌러 짧은 공개 문장을 말하고 인식문을 확인한다. TTS는 Android 성공 확인 전까지 기본 시연에서 제외한다.
4. root09 PASS와 해당 프런트엔드 빌드의 실행 준비 확인 후 촬영한다. 성공한 원본과 촬영 시각·빌드·장치/브라우저·실제 대기시간을 보존한다.

첫 화면과 문화장소 샷에 다음 표시를 유지한다.

> 공개 샘플 사진을 모니터에 띄워 비추는 해커톤 현장 시연입니다. 실제 유적 현장 촬영이 아닙니다.

노트북에서 파일을 직접 올렸으면 **“공개 샘플 사진 업로드 시연”**으로 표시한다. 모델은 선택·샘플링된 프레임을 분석한다. **연속 영상 전체 추론·영상 전체 기억**, 실제 현장 위치 확인 또는 서비스의 영상 녹화 기능으로 설명하지 않는다.

## 90초 백업 샷리스트·대본

아래 시간은 편집 목표이며 모델 응답시간 실측이 아니다. 라이브는 같은 조작 순서를 사용하되 실제 지연을 그대로 포함한다.

| 시간 | 화면·조작 | 진행자 대본 |
|---|---|---|
| 0–10초 | 모니터의 샘플과 Android 후면 미리보기, 시연 표시·출처 | “공개 샘플을 비춰 문화장소를 살펴봅니다.” |
| 10–22초 | 자동 관찰이 반환한 실제 확인 질문, 사용자의 장소 확인·기준점 선택 | “먼저 확인 질문을 받고, 장소와 기준점은 제가 확인합니다.” |
| 22–60초 | 질문 전송 때 현재 프레임 캡처(명시 고정 시 고정 사진), 실제 대기·한글 이름·문화 설명·근거 | “질문에 연결된 장면의 설명과 출처를 함께 확인합니다.” |
| 60–78초 | 실제 반환된 주변 식당과 거리·수록 범위·OSM 표시 | “선택한 기준점 주변에서 수록된 식당을 찾습니다.” |
| 78–90초 | 카드 다운로드 후 해당 파일 열기 | “이 안내와 출처를 카드로 저장합니다.” |

관찰 단계는 확인 질문까지만 보여준다. 아직 확인하지 않은 장소의 역사 설명을 앞당겨 붙이지 않는다. 실제 지연이 위 시간에 맞지 않으면 root가 검수한 범위로 줄이며, 수동 질문을 선제 제안으로 소개하지 않는다. 저장·식당 지도 등 실패한 기능은 성공 샷으로 대체하지 않고 최종 영상 범위에서 제외한다.

## 녹화 방법

- **Android 내장 녹화:** 빠른 설정의 화면 녹화 → 제공되는 오디오 옵션 선택 → 짧은 시험 녹화 → 중지·재생 확인 → 본 촬영. 제조사별 메뉴와 오디오 지원은 기기에서 확인한다. 마이크 입력과 녹화가 충돌하면 외부 촬영으로 전환한다.
- **외부 촬영:** 사용 가능한 다른 휴대폰·카메라·노트북 웹캠을 고정해 Android 화면과 조작 손을 찍는다. 샘플 모니터를 비추는 구도가 보이게 하고 글자 가독성을 먼저 확인한다. **USB 미러링·드라이버·새 앱 설치는 필수가 아니다.**
- **Playwright 브라우저 백업:** root가 준비한 녹화 환경에서 실제 서비스에 접속해 실제 샘플·요청·응답·다운로드 흐름을 기록한다. 녹화 종료 후 영상 파일을 열어 재생과 가독성을 확인하고 실제 성공 부분으로 최대 90초를 만든다. **이 백업은 무음 영상으로 준비**하며 화면 자막 또는 발표자의 현장 설명을 사용한다. 마이크·TTS 성공 증거로 쓰지 않는다. 세션 쿠키·토큰·인증 상태 파일을 영상 산출물에 포함하지 않는다.

어떤 방식이든 **프레임·답변·지도 마커를 합성하거나, 다른 요청의 결과를 현재 요청에 붙이지 않는다.** 실제 브라우저 녹화에도 가짜 응답 주입이나 성공 화면 재현을 쓰지 않는다.

응답 대기를 줄였으면 해당 전환에 **“응답 대기 구간 편집 — 원본 대기 XX초”**를 표시한다. XX는 원본 실측값만 쓴다. 배속은 배속률을 표시한다. 원본은 보존하며 편집본 길이를 모델 속도로 주장하지 않는다. 사전 녹화에는 **“사전 녹화 / 촬영 시각·빌드”**, Playwright 백업에는 **“실제 브라우저 흐름·무음”**을 함께 표시한다.

## 현장 실패 대체와 인계

- **접속·카메라·음성 문제:** root가 확인한 노트북 Chrome으로 전환한다. 텍스트 입력·파일 업로드를 사용했다면 실제 방식을 명시한다. 작성자가 터널·서비스를 재시작하지 않는다.
- **모델 대기·근거 오류:** 추가 요청을 연속 실행하지 않는다. 남은 데모 슬롯만큼 검수된 백업을 발췌하거나, 촬영 시각을 표시한 기존 성공 카드를 설명한다. **210초에는 발표 본문으로 복귀**한다.
- **미확인 장소·0건·저장 실패:** 실제 확인 질문·수록 범위·실패 상태를 보여준다. 성공한 다른 요청을 같은 실행처럼 연결하지 않는다.
- **최종 전달:** root·발표 담당이 원본과 90초 편집본, 출처 표시, 잘라낸 대기시간, 카드 일치를 확인한다. Android TTS·agent09 QA·주기 분석은 확인된 범위만 발표에 반영한다.

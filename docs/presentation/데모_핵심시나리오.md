# 90초 핵심 데모: 광화문 문화 → 주변 식사 → 카드 저장

기준: 2026-10-07 사용자 최신 인계. 운영자용 순서이며 이번 문서 작성 자체는 실행 PASS가 아니다. 기존 런북은 그대로 사용한다. 커밋은 root 담당.

## 시작 전

- 노트북에 [광화문 CC0 샘플](../../data/samples/heritage-demo.jpg)을 띄우고 Android 카메라로 비춘다. 화면/발표에 **“통제된 공개사진 입력(controlled photo) · 현장 촬영 아님”**을 표시한다. 사진: H. Y. Shin 000, Wikimedia Commons, CC0 1.0, 2018년 촬영. [사용권·출처 기록](../../data/samples/heritage-license.json).
- 실장소 모드·한국어로 시작한다. 사진 입력과 질문이 보이도록 한다. 자동 관찰은 기본 끔: **실제 해당 휴대폰 전체 흐름 PASS를 root가 확인한 경우에만 선택적으로 사용**한다. 카메라/캡처/마이크 개별 PASS를 자동동행 PASS로 확대하지 않는다.
- 수동 카메라 캡처를 기본으로 준비한다. 카메라가 막히면 같은 파일을 직접 업로드하고 “파일 입력으로 전환했다”고 말한다. 자동 관찰이 확인 질문을 만들지 못해도 반복 호출하지 말고 수동 선택으로 진행한다.
- 장소 확인은 운영자가 **광화문을 명시적으로 선택**한다. 지도 기준점 선택이지 자동 장소 인식의 성공이나 실제 GPS 위치 증명이 아니다. 시작점이 경복궁/식당으로 남지 않았는지 확인한다.

## 90초 목표 순서

아래 시간은 진행 예산이다. 사용자 인계의 run12에서 관찰→문화 질문→주변 식사 응답 대기는 각각 약 **8초·18초·24초**였으나, 고정 지연·SLA·항상 90초 완료를 약속하지 않는다. 실제 대기 화면을 유지하고 중복 클릭하지 않는다.

| 목표 구간 | 운영자 행동 | 보여줄 것·말할 것 |
|---|---|---|
| 0–10초 | 노트북 사진과 Android 화면을 함께 보여주고 수동 캡처/관찰 시작 | “공개사진을 휴대폰으로 비추는 통제된 테스트입니다.” |
| 10–25초 | 응답을 기다린 뒤 후보 확인 또는 장소 선택 목록에서 **광화문** 선택 | “사진만으로 단정하지 않고 제가 광화문을 선택해 지도 기준점을 정합니다.” 선택 자체로 요청이 시작되면 완료까지 기다린다. |
| 25–50초 | **“광화문의 이름과 역사적 의미를 알려줘”** 입력·전송 | 이름·문화 설명의 실제 응답, 출처, 미확인을 보여준다. “광화문은 경복궁의 정문으로 같은 궁궐 단지입니다.” 역사 답변은 실제 근거에 있는 범위만 읽는다. |
| 50–80초 | **“주변 식사로 이어보기”** 버튼 클릭. 광화문을 기준점으로 유지 | 토속촌 등 수록된 결과와 **선택한 광화문 지도 지점 기준 직선거리**를 보여준다. 도보 경로나 도보시간, 현재 영업·알레르기 안전을 보장하지 않는다. |
| 80–90초 | 현재 유용 결과의 **HTML·JSON을 각각 다운로드/저장**하고 실제 파일이 생겼는지 확인 | HTML은 사용자가 읽는 카드, JSON은 결과·근거를 확인할 산출물이라고 설명한다. **여기서 종료한다.** |

**식당 결과 카드는 저장 전에 누르지 않는다.** 최신 인계상 식당 클릭 후 이어지는 4번째 메뉴 단계는 실패 중이다. 이번 핵심 경로는 주변 식사 결과와 HTML·JSON 저장까지이며 메뉴 상세 성공을 주장하지 않는다. 보이는 식당 카드를 손가락으로 가리키되 탭하지 않는다. 문화 응답 보존이 필요하면 다음 요청 전에 먼저 내려받되 90초 예산을 조정한다.

## 지연·실패 시

- 90초를 넘길 것 같으면 진행 중이라고 밝히고 이미 성공한 단계까지만 보여준다. 로딩을 성공처럼 설명하거나 임의로 재요청하지 않는다.
- 카메라 실패 → 같은 CC0 파일 업로드 → 광화문 수동 선택. 관찰 후보가 안 나와도 자동 인식 성공을 주장하지 않는다.
- 응답 실패/의미 오류 → 그 상태를 설명하고, 출처·실행 시점이 표시된 사전 실제 결과 카드/녹화를 **보조 자료**로 전환한다. 사전 결과를 방금 생성한 결과처럼 제시하지 않는다. 실패한 결과를 성공 카드로 저장하지 않는다.
- 음성 인식·TTS는 90초 필수 단계가 아니다. 텍스트 질문을 준비하고, 휴대폰 TTS가 미검증이면 발화 성공을 주장하지 않는다.

## 5분 발표 안에서의 배치

| 구간 | 내용 |
|---|---|
| 0:00–0:35 | 사용자 문제와 문화·역사 맥락을 근거로 설명하고 행동까지 이어주는 목표 |
| 0:35–1:00 | NVIDIA 모델 판단 → 허용 도구/근거 → OpenShell 통제 → 결과 카드 구조 |
| 1:00–2:30 | 위 90초 실제 흐름; 대기가 길면 다른 설명 시간을 줄이고 상태를 정직하게 표시 |
| 2:30–3:20 | **실제로 수행한 OpenShell 경계 11개 체크 PASS**와 정상 호출 근거 제시. [기존 결과 JSON](../runtime/evidence/boundary-combined-verdict.json)의 체크 범위, 정책·실행 버전을 설명. 이번 발표 준비에서 새 시험을 실행한 것으로 말하지 않음 |
| 3:20–4:10 | 저장 HTML·JSON의 근거와 미확인, 확인 질문의 역할, 문화→식사 연결의 가치 |
| 4:10–5:00 | 아래 범위 제한, 재현 방법·마무리 및 현장 질문 대응 여유 |

안전성은 11개 체크의 시험 범위 안에서 설명한다. 모델의 모든 오류·모든 공격을 차단했다는 주장은 하지 않는다. 영상은 보조이며 작동 데모와 실행 가이드를 대체하지 않는다.

## 반드시 지킬 설명 범위

- **수록 장소는 3개:** 경복궁, 그 정문인 광화문, 토속촌. 전국 장소 검색·전국 맛집 추천으로 소개하지 않는다.
- **최근 영상 기억 없음.** 현재/마지막 샘플 사진과 대화를 사용하며, 연속 영상 전체를 업로드해 이해하는 서비스가 아니다. 카메라 미리보기와 분석용 샘플 프레임 전송을 구분한다.
- 광화문 기준점은 **사용자 선택**이다. 사진 촬영 지점이나 GPS 자동 추정으로 소개하지 않는다.
- 자동 관찰·TTS·메뉴 상세는 실제 검수 범위에 따라 별도로 말한다. 핵심 시연의 성공 기준은 문화 질문 → 주변 식사 결과 → 실제 HTML·JSON 저장이다.
